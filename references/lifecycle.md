How a TUI owns the terminal: cleanup on every exit path (including SIGTERM), the exit status, suspend and handoff to `$EDITOR` or a shell (and what replaces Ctrl-Z on Windows), resize, logs, non-blocking I/O, render scheduling, and how to test it (state tests → golden frames → PTY flows). The API names live in each framework file, linked by section below.

`measured` = run at the pinned framework versions (2026-10, isolated `tmux -L`); `derived:` = our inference. Shell-side exit codes and signals: [cli-contract.md](cli-contract.md).

## 1. Lifecycle contract

| # | Rule | When | Concrete example | Source |
|---|---|---|---|---|
| LC1 | **Restore the terminal on every exit path**: raw mode off, cursor visible, alt screen left, every enabled mode disabled, SGR reset. Paths: normal quit, Ctrl-C / SIGINT, SIGTERM, error return, panic / uncaught exception (SIGKILL cannot be cleaned up). **Prefer framework-managed cleanup**; add your own signal handler only where the framework has none, and make it end in the same managed path | every full-screen or inline TUI | Ratatui `ratatui::run(…)` installs a panic hook and restores; a shell left without echo after a crash is the bug this prevents (user fix: `reset` or `stty sane`) | [ratatui.md](frameworks/ratatui.md) §3, §13 #2 |
| LC2 | **Pair every mode you enable with its disable**, in reverse order, in the cleanup path: mouse tracking, bracketed paste, focus reporting, kitty keyboard flags, alt screen, hidden cursor | any app that enables a mode itself (not through the framework) | Ink has no mouse: enabling `\x1b[?1002h\x1b[?1006h` means sending the matching `l` sequences on exit, or clicks print `^[[<0;12;5M` into the shell | [ink.md](frameworks/ink.md) §7; sequences in [terminal-escapes.md](terminal-escapes.md) |
| LC3 | **Suspend / handoff is not exit.** To run `$EDITOR`, `$PAGER`, a shell or Ctrl-Z: stop reading input (a live reader steals the child's keys), restore the terminal, run and wait, re-enter the modes, **reload data the child may have changed**, clear and redraw the full frame. Never unmount or quit an app that must resume. **Ctrl-Z in raw mode does not suspend by itself** (the terminal no longer turns it into SIGTSTP): implement it (restore → SIGTSTP → on SIGCONT re-enter, reload, redraw) or leave it unbound ([interaction.md](interaction.md#1-default-key-bindings) "Never give another meaning to"). Job control is Unix-only: LC11 | any "open in editor", shell-out or suspend key | `e` opens the selected file in `$EDITOR`; on return the list re-reads it (new mtime, new size) and repaints every cell. A redraw alone repaints the old model | Ratatui spawn-vim recipe (https://ratatui.rs/recipes/apps/spawn-vim/); §2 rows "handoff", "Ctrl-Z" |
| LC4 | **Re-layout on every resize** from the size the framework reports; never cache the startup size. Below the minimum show the too-small screen and keep handling resize and quit. Coalesce bursts only when layout is expensive | full-screen and inline apps | drag the window from 120 to 60 columns: the layout switches to the single-pane fallback without a restart | [layout-archetypes.md §2.1-2.2](layout-archetypes.md#21-size-classes-and-what-to-show); [terminal-capabilities.md](terminal-capabilities.md) D10 |
| LC5 | **Logs never on the TUI's screen.** While the UI runs, stdout and stderr belong to it (for an inline picker stdout is the result). Log to a file or a framework console; show user-facing errors in the message line; print the full error after the terminal is restored | always | Bubble Tea `tea.LogToFile("debug.log", "debug")` + `tail -f debug.log` in another pane | [bubbletea.md](frameworks/bubbletea.md) §3, §13 #8 |
| LC6 | **Never block the event/render thread** on disk, network or subprocess work: run it as a command, task or worker and deliver the result as a message; show the `busy` state and keep cancel working | any I/O | a slow `git log` runs in a worker; the list shows `⋯ Loading commits`, `esc` still cancels | [layout-archetypes.md §2.3](layout-archetypes.md#23-states-every-archetype-must-design) |
| LC7 | **Render on change, not in a busy loop**: redraw on input, data, resize or an intentional tick; an idle app uses ~0 % CPU. Tick only while something animates (spinner 70-130 ms) or at the slowest rate that shows change (ages: 1 s or slower) | every app | the spinner tick is scheduled only while a job runs; an `htop`-style app at rest wakes once per sample, not per frame | [visual-vocabulary.md](visual-vocabulary.md) V6 |
| LC8 | **No TTY, no full-screen UI.** Piped stdout or CI: behave as a one-shot CLI (plain output, exit codes), or, for a picker, draw on `/dev/tty`; if no terminal can be opened, fail with a message naming the non-interactive flag | CLIs that are sometimes scripted | `mytool list | head` prints rows; `mytool` alone opens the UI | [layout-archetypes.md](layout-archetypes.md#product-shapes) P2; clig.dev; the full shell contract (TTY checks per stream, SIGPIPE, exit codes, `--json`): [cli-contract.md](cli-contract.md) §3-§5, checks SH-01, SH-05, SH-07, SH-08 |
| LC9 | **SIGTERM: the same cleanup as quit, then exit 143** (128 + 15). Defaults differ (§2 "SIGTERM" rows): only Ink restores *and* reports 143; Textual and Ratatui die with raw mode, the alt screen and a hidden cursor left; Bubble Tea and gum restore but report a normal quit. Route the signal into the framework's quit path (a flag, a message, `exit(...)`); never draw or restore from inside a low-level handler. SIGKILL cannot be handled | every full-screen or inline TUI, above all under `timeout`, `docker stop`, systemd or a supervisor | `kill -TERM $pid` from another pane → `echo $?` prints 143 and the restore check (below) passes | measured (framework tables); [cli-contract.md](cli-contract.md) CC5; bash: "128+N" for a fatal signal N |
| LC10 | **The exit status reaches the process.** What the framework hands back (Bubble Tea's `Run()` error, Textual's `return_code`, Ink's `waitUntilExit()` outcome, Ratatui's closure result) does not become the process status by itself: map it **after** the terminal is restored. 0 done · 1 error · 130 cancelled (Ctrl-C is a key in raw mode, so most frameworks report 0) · 143 SIGTERM. No hard exit (`os.Exit`, `process.exit()`, `std::process::exit`) before restore | every app whose caller reads `$?`: scripts, pickers, CI | Textual: `app.run()` then `sys.exit(app.return_code)`; `self.exit(return_code=3)` → status 3 (measured) | framework tables (§2 row "exit status"); [cli-contract.md](cli-contract.md) CC2 |
| LC11 | **Windows: no job control.** There is no SIGTSTP: Textual `suspend_process` is a no-op, Bubble Tea ignores `tea.Suspend`. Offer a shell-out key instead (the LC3 handoff running `%COMSPEC%`, `exit` returns to the app) and show its hint instead of `ctrl+z suspend`. `kill`/`TerminateProcess` cannot be caught, but console close, logoff and shutdown can: Go delivers them as `syscall.SIGTERM`, Node as `SIGHUP` (about 10 s before termination), so the LC9 path still runs | apps that ship on Windows | the footer shows `ctrl+z suspend` on Unix and `! shell` on Windows; both keys go through the same handoff code | Go `os/signal` doc "Windows" (https://pkg.go.dev/os/signal); Node "Signal events" (https://nodejs.org/api/process.html#signal-events); framework tables |

**Restore check** (`derived:`, any framework): after `./app` exits, `echo $?` (LC10), then `stty -a | tr ' ' '\n' | grep -xE -- '-?(icanon|echo|isig)'` must print the three flags without `-`; inside tmux also `tmux display -p '#{alternate_on} #{cursor_flag}'` = `0 1`. Comparing `stty -g` before and after is noisy: on macOS a clean Bubble Tea quit changed only `pendin` (measured). Run it once per exit path (quit key, Ctrl-C, `kill -TERM`, a forced error, a forced panic); afterwards typed text must echo, the cursor must be visible and a mouse click must not print escape codes.

## 3. Test pyramid

Bottom-heavy: many cheap state tests, a golden frame per state × pinned size, one or two real-terminal flows. Per-framework recipes: each framework file's §11-12.

| Layer | Test | Pin | Tools here | Per framework |
|---|---|---|---|---|
| **1. State / unit** (most tests) | update logic, key → action mapping, sort / filter / parse, command construction, selection kept by id, stripe parity (layout-archetypes §2.4 Z5) | no terminal | — | Bubble Tea `Update(msg)` is pure; Ratatui `widget.render(area, &mut Buffer::empty(area))`; Textual Pilot `press` + assert attributes; Ink pure helpers + `ink-testing-library` `stdin.write` (each §11) |
| **2. Golden frames** (one per state × size) | the rendered frame for `normal`, `empty`, `busy`, `error`, `toosmall` ([formats.md](formats.md#frame-naming)) | sizes **80x24, 60x24** (floor test), **the declared minimum and one below it**, 120x30; profiles **truecolor, 16 colors, NO_COLOR**; clock injected, animations off, spinner frame 0 | the proto-starters' `--frame --cols --rows --theme --depth` mode (keep it when you copy a starter); `compare.py design.mock frame.ansi -o cmp.html` against the mockup | Bubble Tea `x/exp/golden` on `View().Content`; Ratatui `TestBackend` + `insta` + `buffer_to_ansi`; Textual `frame_to_ansi` or `snap_compare` (SVG); Ink `renderToString(tree, {columns})` (each §11-12) |
| **3. PTY end-to-end** (1-2 flows) | launch → navigate → act → quit; one resize mid-run; one handoff (`EDITOR=true`); one Ctrl-C and one `kill -TERM`, each with its `$?`; then the restore check (§1) | real terminal sizes | `capture_tui.sh -s 80x24 -s 60x24 -k "Down Enter" -o OUT -- CMD` (later sizes resize the running app) | Bubble Tea `teatest/v2` (real program, in-memory I/O); Textual `run_test` (headless Pilot); any binary: `capture_tui.sh` ([choosing.md](frameworks/choosing.md) §2) |

- **Determinism**: pin the size and the color profile (Charm apps downgrade inside tmux unless `TERM=xterm-256color COLORTERM=truecolor`, [bubbletea.md](frameworks/bubbletea.md) §10), inject `now` instead of reading the clock in render ([ink.md](frameworks/ink.md) §8), turn animations off (`TEXTUAL_ANIMATIONS=none`, [textual.md](frameworks/textual.md) §11).
- **What PTY flows are for**: lifecycle and real-keyboard integration only. Frame correctness belongs in layer 2, logic in layer 1; a failing PTY flow should point to a missing lower-layer test.
