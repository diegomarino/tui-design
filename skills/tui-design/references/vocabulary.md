## 1. How to read the master table

- A cell names the exact component, class, type or function, and the package when it is not obvious. `— (compose: …)` = no built-in; the recipe after "compose" is the idiomatic way to build it.
- Shorthand: **BT** `tea` = `charm.land/bubbletea/v2`; `lg` = `charm.land/lipgloss/v2` (+ `lg/table`, `lg/tree`, `lg/list`); `bubbles/x` = `charm.land/bubbles/v2/x`; `huh` = `charm.land/huh/v2`. **Ratatui**: `ratatui::widgets::*`, `ratatui::layout::*`, `ratatui::style::*`, `ratatui::text::*`; third-party crates are named. **tview** = `github.com/rivo/tview` (on `tcell`). **urwid** = `urwid`. **blessed (py)** = Python `blessed` (jquast), not the abandoned Node `blessed`.
- Rows follow the fixed concept list of the skill ([formats.md](formats.md#vocabulary-ids)). Row order is the same in every file; the concept names are the ids to use in your own prose.
- Legend for pipes in cells: `\|` is a literal `|` in code.

## 3. Concept → schema ids (so designs and audits use the same names)

`Region role` and `Element type` are the enum values in `schemas/tui-description.schema.json` (`$defs/region.role`, `$defs/element.type`). "Token" names the main color tokens from `themes/_tokens.json` the concept is drawn with (see `color-tokens.md` for rules). "—" = the concept is not a visible thing (or has no region of its own); describe its *effect* instead.

| Concept | Region role(s) | Element type(s) | Main tokens | Notes for describing it |
|---|---|---|---|---|
| app | `screen` | — | `bg.base`, `fg.default` | The whole window; `meta.capture.alternate_screen` records alt-screen vs inline |
| screen/view | `screen` (the active one) | — | `bg.base` | A view change = a different frame state, not a different region |
| layout container (row/column) | — | — | — | Structural only; report the children's regions with their bboxes |

## 4. Terminology traps (same word, different thing)

| Word | Meanings you will meet | Rule of thumb |
|---|---|---|
| **screen** | (1) Textual `Screen` = a view on a stack. (2) The physical terminal window / alt buffer. (3) Node blessed `screen` = root widget. (4) urwid `raw_display.Screen` = output backend. (5) schema role `screen` = the whole-window region | In our prose and schema: *screen* = the whole window; a navigable state is a **view**. Say "Textual `Screen`" when you mean the class |
| **panel** | Textual has **no `Panel` widget**; `$panel` is a color variable, `panel` is a border type, `HelpPanel`/`KeyPanel` are key-help widgets; Rich `Panel` is a bordered renderable; schema role `panel` = generic bordered region | Use **pane** for the bordered box in prose, **panel** only for the schema role |
| **Static** | Ink `<Static>` = append-only permanent output above the live area. Textual `Static` = base widget for text/renderables. Neither means "non-interactive" | Ink: "never rewritten"; Textual: "a label" |
| **Box / Block / Frame** | Ink `Box` = flex container (+ optional border/bg). tview `Box` = base primitive with border. Ratatui `Block` = border + title wrapper, **not a container** (children are rendered into `block.inner(area)`). Ratatui `Frame` = per-draw render target; tview `Frame` / urwid `Frame` = header/body/footer wrapper | Do not read Ratatui `Block` as Ink `Box` |
| **Layout** | Ratatui `Layout` splits a `Rect` into `Rect`s and renders nothing. Textual "layout" = a CSS property. Lip Gloss has no layout engine (string joins) | Ratatui: compute rects first, then render into them |
| **view** | Bubble Tea `View()` renders the whole model and (v2) returns a `tea.View` struct (content + terminal modes); it is not a "screen" | "Screen" in Bubble Tea = a model state you switch in `View()` |
| **viewport** | Bubbles `viewport` = scroll view. Ratatui `Viewport::{Fullscreen, Inline(h), Fixed(rect)}` = *terminal drawing mode* | Ratatui `Viewport` ≈ alt-screen vs inline, not scrolling |
| **canvas** | Ratatui `canvas::Canvas` = shapes (braille). Lip Gloss `Canvas`/`Compositor` = cell layers for overlays. Textual `textual.canvas.Canvas` = internal keyline primitives; Textual has no public drawing widget | Free drawing → Ratatui `Canvas`; modal overlays → Lip Gloss layers |
| **list** | Bubbles `list.Model` (filter + pagination + help). Textual `ListView` (widget items) vs `OptionList` (renderables). tview `List` (menu with shortcuts). urwid `ListBox` = scrolling container for *any* widgets. gum `choose` = a list | Check whether items can be arbitrary widgets (Textual `ListView`, urwid `ListBox`) or text rows |
| **Select** | Textual `Select` = overlay dropdown. @inkjs/ui `Select` and `huh.NewSelect` = inline list (radio-like). tview `DropDown` = overlay | If a dropdown overlay is the design, only Textual and tview give it built in |
| **table** | `lg/table` (static render) vs `bubbles/table` (interactive); `ink-table` (static); Textual `DataTable` (interactive); gum `table --print` (static) | Static vs interactive decides the package |
| **modal** | Textual `ModalScreen` = any overlay screen. tview `Modal` = message + buttons only. urwid `Overlay` = a widget over another | |
| **message** | Bubble Tea `tea.Msg`, Textual `Message` = events. Schema element `message` = a status/feedback line on screen | |
| **widget / component / primitive / bubble** | Textual and Ratatui and urwid "widget"; Ink "component"; tview "primitive"; Bubbles "bubble" (a sub-model, not a function) | Ratatui widgets are short-lived values consumed by `render`; their state (`ListState`, `TableState`) lives in your app |
| **cursor** | (1) the terminal's text cursor (Ink `useCursor`, Ratatui `set_cursor_position`), (2) the highlighted row of a list, (3) the `❯` glyph, (4) Bubbles `cursor` (blinking-cursor sub-model), (5) Textual "block cursor" = list/table highlight | Say "cursor row" vs "text cursor" |
| **focus** | Widget focus (which widget gets keys) vs terminal focus events (`tea.FocusMsg`, `term.focus_events()`, crossterm `FocusGained`) | |
| **header / footer** | Textual `Footer` shows the key hints from `BINDINGS` (so it is a *keybar*). tview/urwid `Frame` header/footer = text slots. Our schema separates `statusbar`, `footer`, `keybar` | Name the *content*: status vs key hints |
| **blessed** | **Node `blessed`** (chjj): widget library, abandoned (last commit 2016, npm 0.1.81). **Python `blessed`** (jquast, 1.50.0): terminal wrapper (colors, input, width math), no widgets. Different projects | Always write "blessed (py)" / "blessed (node)" |
| **inline** | Ink: the default render. Textual: `run(inline=True)`. Bubble Tea: no `AltScreen`. Ratatui: `Viewport::Inline(h)`. All mean "draw below the prompt; leave scrollback" | Opposite of alt-screen; not "inline text" |
| **Style** | Lip Gloss `Style` = immutable value (`Render(s)`). Ratatui `Style` = struct (fg/bg/modifiers). Textual styles = TCSS properties. Ink = props. | |
| **spacer** | Ink `<Spacer/>`, Ratatui `Layout::spacing`/`spacers`, urwid `Divider`/`SolidFill`, tview `AddItem(nil, …)` | |

Verify version-sensitive traps in the source: Textual `BORDER_CHARS` in `src/textual/_border.py` (border type `panel`), Ratatui `Block` in `ratatui-widgets/src/block.rs`.
